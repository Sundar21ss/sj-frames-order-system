LUCKY PLANET STUDIOS | SJ FRAMES — LAPTOP SKIN ORDER SYSTEM

This project includes the customer order form, SQLite order storage, private image uploads, and an admin dashboard.

LOCAL RUN ON WINDOWS
1. Install Python 3.10 or newer.
2. Extract this ZIP and open Command Prompt in the project folder.
3. Create a virtual environment: py -m venv .venv
4. Activate it: .venv\Scripts\activate
5. Install packages: pip install -r requirements.txt
6. Set secrets for this terminal before running:
   set ADMIN_USERNAME=admin
   set ADMIN_PASSWORD=use-a-unique-password-here
   set SECRET_KEY=paste-a-long-random-secret-here
7. Start locally: python app.py
8. Customer form: http://127.0.0.1:5000
9. Admin login: http://127.0.0.1:5000/admin/login

Generate a random SECRET_KEY with Python:
   py -c "import secrets; print(secrets.token_urlsafe(48))"
Use a unique ADMIN_PASSWORD of at least 14 characters. Do not commit passwords or secret keys to GitHub.

PUBLIC DEPLOYMENT (Render)
1. Push this project folder to a private GitHub repository (do not upload customer data, orders.db, or private_uploads).
2. In Render, create a new Blueprint and select that repository; Render will read render.yaml.
3. When prompted, enter a strong unique ADMIN_PASSWORD of at least 14 characters. The SECRET_KEY is generated by Render.
4. The configuration uses a persistent disk mounted at /var/data for orders.db and private_uploads. This requires a Render service plan that supports persistent disks; it is not a free ephemeral-filesystem setup.
5. Wait for deployment to finish, then open the public service URL. Admin URL: https://YOUR-SERVICE.onrender.com/admin/login
6. Test an order using your own test images, verify it appears in the admin dashboard, and verify that opening an image URL while logged out redirects to login.
7. Keep the admin password private. Enable MFA on your hosting/GitHub accounts and keep a separate backup of the database and uploaded images.

SECURITY NOTES
- Uploaded images are stored outside Flask's public static directory and are served only to logged-in admins.
- Forms use CSRF tokens; uploads are size-limited, checked as real images, and re-encoded before storage.
- Production mode refuses to start without a strong persistent SECRET_KEY and a unique ADMIN_PASSWORD.
- HTTPS is expected in production. COOKIE_SECURE=1 requires HTTPS; local HTTP testing should leave it set to 0.
- The SQLite database and uploads are stored under DATA_DIR (defaults to this project folder locally, /var/data on Render).
- The app does not currently send WhatsApp messages, accept payments, or notify you automatically.
- Do not use Flask's built-in development server for public production hosting.
- Before real commercial use, establish a privacy/retention policy and test backups and restoration.

LATEST IMPROVEMENTS
- Admin dashboard includes order summary cards, search, status filter, customer WhatsApp links, private image preview, and status updates.
- Use the “Export Excel” button in the admin dashboard to download a formatted workbook containing all order fields and a summary sheet.
- The application also refreshes orders.xlsx in DATA_DIR after order/status changes. SQLite (orders.db) remains the authoritative database; Excel is a convenient mirror, not a replacement for SQLite.
- After a successful form submission, a centered Thank You popup shows the order reference and offers a WhatsApp confirmation link to the business number. WhatsApp opens with the message prepared; the customer must tap Send. Websites cannot silently send a WhatsApp message through a normal wa.me link.
- In production, DATA_DIR=/var/data, so the live Excel mirror is stored on the persistent disk and is not committed to GitHub.


FORM VALIDATION UPDATE
- WhatsApp numbers are checked in the browser before submission (8-15 digits).
- Invalid WhatsApp input displays an inline message in Customer details and scrolls to that field.
- The form is not submitted for this client-side validation error, so all typed fields and selected files remain in place.
- Server-side validation also preserves entered text, selections and checkboxes. Browsers do not permit websites to repopulate file inputs after a server round-trip; if a server-side upload validation error occurs, the customer may need to select the files again.

LOGO UPDATE
The customer form header now uses static/logo.svg, a custom metallic silver and champagne-gold planet emblem with no purple. Replace static/logo.svg to change the planet mark.


DEPLOY PACKAGE SAFETY NOTE
This deployment package intentionally excludes orders.db, orders.xlsx, private_uploads contents, and the local venv. Start with an empty database. Set ADMIN_USERNAME, ADMIN_PASSWORD (14+ characters), and SECRET_KEY as described above before running locally.
